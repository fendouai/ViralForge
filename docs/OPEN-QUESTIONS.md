# 待确认清单

> 开发已按「美妆 / 鞋包 / 家居」三个通用品类、ViralForge 暂名、深色实验室视觉完成 MVP。
> 以下事项需要业务/法务/品牌确认，不阻塞当前 demo，但会影响对外发布。

## P0 · 发布前必须确认

1. **项目名与资产**
   - 暂名 ViralForge；是否启用中文名（如「爆款工坊」）？
   - GitHub 组织名、npm 包名、域名是否已抢注？建议：`viralforge` / `@viralforge/cli` / `viralforge.ai`（需查重）。
   - 建议：确认后统一替换 README、Skill、CLI 包名与页面字标。

2. **部署账号**
   - 当前无 Vercel / GitHub 登录态，只完成本地部署。
   - 需要：`VERCEL_TOKEN`（或 Cloudflare / 指定平台凭据）才能给固定公网链接。
   - 渲染 worker 不能跑在纯静态托管上，需要独立 Node + FFmpeg + Chromium 容器。

3. **法务边界**
   - AI 生成标识的具体文案与位置（画面角标 + 元数据）是否符合目标市场要求？
   - 平台条款：是否接受「仅支持本地上传」作为开源版默认？
   - 隐私政策、用户上传素材的存储与删除策略。

4. **对外口径**
   - 确认 README 不写云端上线时间、不写 WearAI 品类差异化、不写「绕过检测」类表述。
   - 确认「结构复刻，不搬运原片画面/音乐/文案」作为统一话术。

## P1 · 影响产品化

5. **模型与成本**
   - 首批支持哪些视频模型（Seedance / 可灵 / Wan2.2 / Hailuo）？
   - 单条变体的目标成本区间（当前演示口径 ¥0.3–0.6）是否成立？
   - 是否接受「用户自带 Key」作为开源版默认？

6. **商品一致性**
   - 云端一致性模型由哪条路线提供？P1 的验收标准是什么（CLIP/颜色/结构抽检通过率）？
   - 开源版只做模板约束，是否足够支撑「商品不变形」的宣传？

7. **案例与素材**
   - 三个案例（精华 / 托特包 / 香薰灯）是否换成 WearAI 真实客户产品？
   - 是否需要真实达人出镜/授权数字人？当前为自制模拟关键帧。
   - 是否需要英文版页面与英文字幕（WearAI 用户以美国为主）？

8. **人力与排期**
   - 文档建议 ViralForge 单独配 2–3 名工程师；实际投入是谁？
   - 拆解版是否赶 11 月底黑五？复刻版是否赶 2027 春节年货节？
   - 是否把「每周 Top 50 拆解」与 X 机器人纳入首发运营？

## P2 · 可选增强

9. **开源治理**
   - 许可证：本项目用 Apache-2.0；是否加 NOTICE / 贡献者协议？
   - 是否接受社区 PR 接入新模型 provider？
   - 是否公开 LearnBench 式的评测（拆解准确率 / 复刻一致性）？

10. **数据与合规**
    - 是否需要报告卡片的公网托管与短链？当前为本地 hash 路由。
    - 是否需要团队空间、历史记录、成本看板？
    - 删除/导出用户数据的 SLA。
